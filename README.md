# OBD2 CAN Gateway

An open-source **CAN ↔ USB** gateway for reading OBD-II diagnostic data from a car, built on the **STM32F303K8**.
This is an **educational** project: the goal is to learn C on a microcontroller, the CAN bus, ISO-TP and OBD-II, and how to build embedded projects with CMake.

> **Status:** early prototype. Hardware configuration done, first CAN test in loopback mode in progress.

---

## Project goals

- Understand the CAN bus from both the hardware and software side: bit timing, arbitration, ACK, filters, error handling.
- Implement portable protocol modules in C: **SLCAN** (Lawicel), **ISO-TP** (ISO 15765-2), **OBD-II** (SAE J1979).
- Keep a clean layered architecture: protocol logic independent of the HAL and of the specific microcontroller.
- Run unit tests on the host PC, with builds and CI based on CMake.
- Long term: a custom PCB with the MCU and transceiver integrated into an OBD connector.

## How it works

```
 Car (OBD-II)                Prototype                         PC
┌──────────────┐  CAN-H/L  ┌──────────┐  TX/RX  ┌────────────┐  USB (VCP)  ┌──────────────┐
│ HS-CAN       │──────────▶│ TJA1051  │────────▶│ STM32F303K8│────────────▶│ SavvyCAN /   │
│ 500 kbit/s   │◀──────────│ (CAN Pal)│◀────────│ bxCAN+UART │◀────────────│ python-can / │
│ pins 6 / 14  │           └──────────┘         └────────────┘   SLCAN     │ slcand       │
└──────────────┘                                                           └──────────────┘
```

The STM32F303K8 has no USB peripheral. In the prototype, communication with the PC goes through the **ST-LINK virtual COM port** (USART2) on the Nucleo board. The final PCB version will use an MCU with native USB.

### ⚠️ Safety when connecting to a car

- **Disable the 120 Ω termination** on the module. The car's bus is already terminated.
- Make the first connection in **Silent mode** (listen only: no transmitting, no ACK) so you don't disturb the ECUs.
- **Do not connect pin 1** of the OBD connector. On GM vehicles it carries single-wire CAN (33.3 kbit/s), which the TJA1051 does not support.
- This is an educational project. Use it at your own risk.

## MCU configuration

| Parameter | Value |
|---|---|
| Clock | HSE 8 MHz (bypass, MCO from ST-LINK) → PLL ×9 → **72 MHz** |
| APB1 (bxCAN, USART2) | **36 MHz** |
| CAN | **500 kbit/s**: prescaler 4, BS1 = 15 TQ, BS2 = 2 TQ, SJW = 1 TQ, sample point 88.9 % |
| USART2 (VCP) | 115200 8N1, PA2 (TX) / PA15 (RX) |
| LED | LD3 on PB3 |

The peripheral configuration is stored in [`firmware/firmware.ioc`](firmware/firmware.ioc) (STM32CubeMX).

## Building

### Requirements

- [STM32CubeMX](https://www.st.com/en/development-tools/stm32cubemx.html), only needed when changing the peripheral configuration
- [STM32CubeCLT](https://www.st.com/en/development-tools/stm32cubeclt.html): `arm-none-eabi-gcc` toolchain, CMake, Ninja, ST-LINK GDB server
- VS Code with the **STM32Cube for Visual Studio Code** extension (recommended)

### Firmware

```bash
cd firmware
cmake --preset Debug
cmake --build --preset Debug
```

Output: `firmware/build/Debug/firmware.elf`.

In VS Code: open the `firmware/` folder, select the **Debug** preset, build with **F7**, debug with **F5**.

### Flashing without an IDE

```bash
STM32_Programmer_CLI -c port=SWD -w firmware/build/Debug/firmware.elf -v -rst
```

### Host tests

```bash
cmake -S tests -B build/tests
cmake --build build/tests
ctest --test-dir build/tests --output-on-failure
```

## Usage

When the Nucleo is connected over micro-USB, the system shows a **STMicroelectronics STLink Virtual COM Port**. Settings: **115200 8N1**.

The gateway will speak the **SLCAN** protocol, so it works with existing tools:

- [SavvyCAN](https://www.savvycan.com/) for viewing and analysing traffic
- [python-can](https://python-can.readthedocs.io/) with `interface="slcan"`
- Linux: `slcand` + `can-utils` (`candump`, `cansend`)
